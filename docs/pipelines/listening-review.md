# 统一试听页：选择即写入本地文件

> 本文件是实验试听模板、保存和 Agent 读取的统一规范。当前任务见 [PLAN](../../PLAN.md)，评价目标见 [统一自检](self-check.md)。

## 用户操作

1. Agent 为当前实验生成 `listen/index.html`，启动本地服务并打开网址。
2. 用户播放音频，直接选择甲/乙、评分、问题标签或填写备注。没有导出按钮，也没有额外提交步骤。
3. 页面显示 **“已保存到本地文件，可以告诉 Agent‘继续’”** 后，用户在对话中说“继续”。
4. Agent 直接读取该实验的本地评分文件，结合自动自检和已有证据推进下一步，不再索要下载的 JSON。

没有评完所有组也可以继续；未评项保持待试听。疲劳表示本轮难以判断，不算平局或模型胜负。

## 已有要求的位置

这一偏好原先已写在 [语音资产管线](voice-assets.md) 的“审核（网页，点击即写盘）”和“关键约定”。所有审核、参考音选择和盲听评分继续直接写盘；实验试听的模板、保存确认和继续入口集中在本文件。旧 PLAN 的第10节已随历史计划归档，当前入口与本规范保持一致。

## 同一个模板

普通 gate、Phase 5A、Phase 5A2、LoRA pilot 都通过 `src/character_tts/web/listen_template.py` 生成页面。各实验的数据构建保留在 `listen_page.py`，共同使用：

- 相同样式、播放组件、四维评分、文本完整性及备注。
- 同一保存确认、重试、刷新恢复、解盲及疲劳交互。
- 同一实验及音频身份绑定；甲/乙顺序改变或音频重新生成后，不套用旧选择。
- LoRA 配对继续使用低疲劳分组、首次印象和缺陷标签；主观评分不预填。

未来统一自检页面也必须复用这个模板，不能复制另一套 HTML 和保存逻辑。自动评分可另列证据，不能写入用户主观评分栏。

入库审核、参考音选择是其他操作类型，保留其专用控件和直接写盘接口；生产生成 WebUI 也不改成试听实验页。

## 启动与继续

Agent 在用户本地仓库运行，`--bundle` 指向实验根目录，而不是 `listen` 子目录：

```bat
.venv\Scripts\python.exe scripts\ingest\serve_review.py --bundle outputs\gates\<experiment_id> --port 7865 --open-browser
```

根网址 `http://127.0.0.1:7865/` 会打开该实验的试听页。不同并行实验使用不同端口。本地服务必须保持运行；`file://` 直接打开只展示内容并提示正确入口，不启用评分，也不退回手动导出。

用户说“继续”后，Agent 运行：

```bat
.venv\Scripts\python.exe scripts\eval\read_listening.py --bundle outputs\gates\<experiment_id>
```

| 读取状态 | Agent 处理 |
|---|---|
| `RATED` | 使用已保存选择，报告已评与未评数量，再结合自检决定下一步 |
| `UNCERTAIN_FATIGUE` | 使用已经明确的记录，停止扩充试听；不把未听项算成平局 |
| `PENDING_USER_LISTENING` | 本轮没有有效选择，不虚构人耳通过 |
| `BLOCKED` | 核查实验身份、音频 hash 或文件完整性；不使用旧音频评分作当前证据 |

“继续”表示 Agent 可以读取当前选择并推进既定任务，不表示用户已经评完所有隐藏组。

## 本地文件与保存保证

- `listen/review-contract.json`：当前实验、音频 SHA、甲乙顺序及评分文件身份。
- `listen/listen-ratings*.json`：Agent 读取的完整评分快照，保留各历史实验的既有文件名与顶层数据格式。
- 主 JSON 的 `_page_state`：刷新恢复的数据；`_review`：服务确认时间、版本、已评/未评、疲劳和可读状态。
- `*.json.state`：旧格式兼容副本；主 JSON 是当前数据源。
- `listen/history/<评分文件名>/`：替换实验时保存的历史快照，原来的选择不会被当成新音频选择。

每次选择和备注输入都进入同一个串行写入队列；最后一次改动获得服务成功确认后，才显示已保存。服务返回400/409/500、写盘失败或断开时显示未保存，并保留浏览器草稿用于重试；草稿不是 Agent 可读取的评分证据。

主快照用临时文件加原子替换，避免 Agent 读到半个 JSON。多个页面同时修改同一评分文件时，旧版本不能覆盖新版本。

复用旧实验音频时，模板把已验证 SHA 的外部音频复制进当前试听 bundle，保证本地服务可以播放；文件内容仍与评分绑定的 SHA 相同。

旧格式评分只有在实验、音频 SHA、甲乙顺序能够验证时才自动恢复；不能验证的条目保留为历史记录，不默默套用。内部 `export_*_ratings.py` 仍可由 Agent 用于脱敏归档，它们不是用户的手动导出步骤。

## 验收

核对四类页面共用模板、无下载按钮；真实 HTTP 保存/恢复、连续修改后最终值、服务错误不显示成功、备注未离焦保存、清空、疲劳、实验切换、音频变化与历史评分恢复都应验证。

运行基础回归：

```bat
.venv\Scripts\python.exe -m pytest -q tests\web\test_local_listening.py tests\ingest\test_ingest.py tests\evaluation
```

旧的生成页面需要调用对应页面构建函数重新生成；不需要为更新模板重新合成音频。Agent 应启动更新后的本地服务，再让用户试听。

前端回归可安装 jsdom，并将 `TTS_JSDOM_MODULE` 指向其模块目录，再运行
`tests/web/test_local_listening_dom.py`。它验证真实 DOM 事件与本地 HTTP 写盘，
包括快速连改、备注未离焦、刷新、失败重试、旧标签页冲突、清空、疲劳及
`file://` 只读。这不是完整浏览器的视觉或音频播放测试。

已在未修改的原始代码上复现；本次未改动该路径模块。用户 Windows 的
实际浏览器视觉与音频播放仍由本地 Agent 在复用已有 WAV 时确认。
