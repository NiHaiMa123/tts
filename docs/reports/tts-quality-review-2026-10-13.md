## 1. 结论与证据边界

当前训练会同时改变角色表达习惯和声学细节，因此“习惯更像、音质下降”可以同时发生。现有证据不足以将音质损失认定为 LoRA 不可避免的代价，也不足以直接锁定 DiT、数据污染或过拟合中的某一个为根因。

本次发现三类问题：

1. **确定的代码缺陷**：预处理元数据没有完整传递；被拒绝的语音片段可能重新拼回；删除有声片段后未同步台词；全段拒绝或 VAD 失败没有自动进入下游审核隔离。
2. **确定的机制与评测限制**：LM 和 DiT 联合训练，没有分模块控制音质与习惯；VAD 无法直接清理语音内部磨砂；跨数据版本划分会变化；A/B 脚本与生产推理路径不完全一致。
3. **待验证的音质原因**：训练目标与听感不一致、声学模块适配过强、特定发声样本或 codec 表征影响生成。这些是研究方向，不能写成已确认根因。

尤其需要区分：**某个缺陷已复现，不等于它已在当前 v3 数据中实际触发，更不等于它解释了全部音质退化。**

## 3. 数据预处理问题

### 3.1 被拒绝的语音可能作为间隔重新拼回【已复现，P0】

位置：[preprocess.py](../../src/character_tts/ingest/preprocess.py)，`cut_segments()`。

代码先建立保留段列表，但拼接相邻保留段时直接取：

```python
gap = x[prev_end:s_i]
if len(gap) > max_gap:
    gap = gap[:max_gap]
```

两个保留段之间可能包含已经被标记为 `clipped` 或 `too_short` 的有声段。上述切片没有排除这些区间，短间隔会全部保留，长间隔的前300ms也可能包含被拒绝片段。

本次用原函数、48kHz、默认10ms边缘淡化复现：

- 保留段：0–200ms、450–650ms。
- 削波段：250–400ms，幅值1.0。
- 报告：削波段已列入 `dropped`。
- 实际：输入7200个削波样本，输出仍有7200个，全部重新拼回。

现有测试 `test_cut_segments_drops_nonspeech_and_clipped` 只检查丢弃标签、长度及有限值，没有检查被拒绝内容是否仍在输出，因而没有覆盖这个缺陷。

**修正方向**：明确计算允许保留的间隔区间，排除所有拒绝段；若跨越被拒绝的有声段，应将整条样本送审核或拒绝训练，不能只凭“间隔不超过300ms”接收。

### 3.2 删除有声段后，没有同步修改文本【代码已确认；实际触发量待查，P0】

预处理写回同名 WAV，后续文本仍从原元数据或文件名读取。没有生成剪后转写、时间映射或对齐结果。

一旦真的删除了一个含字的短段或削波段，就会出现：

```text
文本仍包含完整台词
音频却缺少其中的字或短语
```

这可能影响模型学习发音、时长、停顿和结束位置。`<150ms` 本身也不能证明该段是爆音；短促的语气词或有效语音存在被误删的可能。

**修正方向**：优先只做带足够保护边界的首尾静音裁剪。需要删除有声内容的样本先隔离；若保留剩余语音，应建立准确对应的文本，再进行 ASR/对齐辅助检查和必要的人工核对。不能继续使用原完整台词。

### 3.3 原始权威台词和来源元数据没有传入 clean 目录【代码已确认，P0】

涉及：

- [preprocess_audio.py](../../scripts/ingest/preprocess_audio.py)
- [standardize.py](../../src/character_tts/ingest/standardize.py)
- [ludiglot_import.py](../../src/character_tts/ingest/ludiglot_import.py)

导入器将权威台词写到 `inbox/provenance.jsonl`。预处理只遍历 WAV、写镜像 WAV 和 `preprocess_report.jsonl`，没有将这份元数据传递到 `inbox_clean/provenance.jsonl`。

按文档把 `standardize_inbox` 指向 clean 目录后，找不到原元数据就会退回从文件名读取文本。文件名若不是完整逐字转写，或含有替换、截断、编号，训练文本可能错误，来源信息也会丢失。

**修正方向**：逐文件保留权威文本、原始来源 ID、原始音频 hash、处理步骤和剪切区间。元数据保留不能替代3.2的剪后台词核对，两项都必须满足。

### 3.4 全段拒绝、VAD 失败没有自动隔离【代码已确认，P0】

`cut_segments()` 在没有有效段或所有段都被拒绝时，返回原音频并标记 `all_dropped=true`。VAD 失败也会按未剪切处理。

保留原件供人工审核是合理的，但当前：

- 状态只写入预处理报告；
- standardize 不读取该报告；
- freeze 不据此隔离；
- 训练导出只检查基本可读性、时长、有限值、静音及去重/评测泄漏等条件。

因此，原音频仍可能通过后续接收。不能把“保留供审核”自动变成“允许训练”。

**修正方向**：将 `all_dropped`、`vad_missing`、VAD异常及有声内容删除等状态传递至入库索引，设置明确的待审核/拒绝训练状态；人工确认后才解除隔离。

## 4. v3 的 VAD 清洗没有证明磨砂已经被处理

[音频资产管线文档](../pipelines/voice-assets.md)记录：爱弥斯223条音频仅剪掉约29秒，将这些剪切主要归于首尾静音。本次未获取本地逐文件报告来独立核对。

VAD 判断是否有语音，当前片段质检主要判断时长和接近满幅的削波。这些规则不能直接识别：

- 正常幅度下的压嗓、粗糙发声；
- 语音内部的颗粒或编码伪影；
- 特定元音、辅音上的不自然声学细节。

因此不能从“已清洗到v3”推出“训练数据中这些问题已消失”。文档中的“磨砂来自数据声学签名”应作为待验证解释，而非最终诊断。

可用 F0、HNR 等指标定位候选片段，但自然气声、喉化和情绪性发声也会影响这些指标，不能按单一阈值把角色习惯全部删除。应先局部试听，再决定样本处理。

## 5. 联合训练让习惯与声学变化纠缠【机制已确认；音质归因待验证，P1】

官方2.0.3实现中：

- `enable_lm` 同时注入 `base_lm` 和 `residual_lm`。
- `enable_dit` 注入局部扩散生成模块。
- AudioVAE在LoRA训练中冻结。
- 主要优化目标为 `loss/diff` 和 `loss/stop`。

因此“只保留LM”也不等于“只保留语义和说话习惯”：残差LM仍参与声学生成。现有配置没有专门的基模音质保持约束，也没有针对三组模块分别建立听感证据。

官方实现：[LoRA注入与模型结构](https://github.com/OpenBMB/VoxCPM/blob/19b6bf7590025418821a86dcb817504e0ad7e5df/src/voxcpm/model/voxcpm2.py)、[LoRA层与scaling](https://github.com/OpenBMB/VoxCPM/blob/19b6bf7590025418821a86dcb817504e0ad7e5df/src/voxcpm/modules/layers/lora.py)。

合理假设是某些声学适配幅度过强，或学习到了不符合目标的声学模式。但同样需要考虑训练目标、数据代表性、表达分布及codec表征，不能直接认定DiT是唯一原因。

官方训练编码输入16kHz、输出48kHz是正常设计，不应把它误判为平台采样率Bug。冻结的AudioVAE也不会因为这次LoRA而自行获得新的重建能力。锁暝已有codec报告不能直接替代爱弥斯当前音频的诊断。

## 6. 评测和复现问题

### 6.1 A/B 脚本与生产路径不完全一致【已确认，P1】

[gen_aimisi_lora_ab.py](../../scripts/lora/gen_aimisi_lora_ab.py)使用 `42+i`，生产使用 `123+i`。脚本将 `normalize=True` 写入GEN/元数据，但实际直接调用内部生成接口，没有执行文本规范化；生产worker会先规范化文本再分块。

同一个脚本内的base/LoRA仍可比较，不能因此否定所有旧结果；但这些结果不等于当前WebUI生产预设的完整复现，尤其包含数字、符号或规范化会改变文本的情况。

**修正方向**：评测复用生产worker的生成路径，真实记录有效文本、分块、逐块seed、实际参数、模型及adapter身份。不要只在元数据中声明参数。

### 6.2 音频处理会改变数据划分【已复现，P1】

[freeze.py](../../src/character_tts/ingest/freeze.py)使用：

```text
fid = hash(规范化文本 | 音频SHA256)
split = hash(split | fid)
```

预处理改变音频hash，fid随之变化，同一句台词的train/validation/test归属也可能变化。

合成ID验证中，同样200条文本更换音频hash后，67条改变划分，其中30条从train进入validation/test。这只是机制演示，不是当前真实数据的统计。

因此v1、v2、v3之间不能自动视为“只改变音频清洗，训练与验证样本完全相同”。单个版本内审计通过，也不证明跨版本划分稳定。

**修正方向**：按原始语音资产ID分组固定划分，再派生不同处理版本；一个原始语音的不同处理版本保持在同一组。继续保留音频hash用于完整性验证。

### 6.3 训练数据身份和加载版本记录需要补齐【已确认配置差异，P2】

- 爱弥斯角色yaml中的dataset仍指向v1，生产权重指向v3。这不直接改变已加载权重的声音，但默认训练准备脚本读取角色dataset，未来容易导出旧版本数据。
- bootstrap没有固定 `voxcpm` 包版本。
- worker只在官方API显式接受 `revision` 时传递该参数；官方2.0.3 `from_pretrained` 没有该显式参数，内部 `snapshot_download` 也未传入指定revision。配置中的revision不等于运行时已验证的snapshot身份。
- 生产sidecar未记录实际adapter权重hash和加载完整性结果。

这不能证明当前已加载错误模型。更稳妥的实现是显式定位所需本地snapshot，校验实际加载路径及adapter身份，并在实验和生产日志中记录。

## 7. 长文自然度与坏句检测限制【已确认，P1】

[voxcpm_worker.py](../../workers/voxcpm_worker.py)按最多100字分块，每块重新参考同一段声音，块间固定插入200ms间隔。

该策略有助于限制长文音色漂移，但会重置跨块上下文，可能影响情绪延续、语速和停顿衔接；固定间隔还会叠加模型自身生成的静音。它主要影响长文整体自然度，不能单独解释短句LoRA磨砂。

官方 `retry_badcase` 主要检查音频长度相对文本是否异常，不能识别压嗓、颗粒或破音。seed123在已试听样本中较好，也不构成所有新文本的质量保证，后续块实际使用seed124、125等。

应保留逐块文本、seed、时间位置和异常记录，先定位问题块再局部处理。

## 8. 建议处理顺序

### 第一阶段：修数据链路并审计现有v3

1. 修复3.1的拒绝段回流，新增能检查输出内容的回归用例。
2. 完整传递provenance和预处理审核状态。
3. 禁止删除有声内容后继续使用原完整台词；优先保守首尾裁剪。
4. 读取本地v3的预处理报告、入库索引、审核决策和最终train.jsonl，统计上述问题实际触发了多少条、是否进入训练。
5. 按原始语音ID建立跨版本稳定划分；必要时创建新的数据版本，保留历史实验。

验收需要验证真实“输出内容”和“训练接收状态”，不能只验证日志写了dropped、文件变短或数据hash一致。

### 第二阶段：用现有checkpoint做最小分模块诊断

选2–3个最明显有压嗓/颗粒问题的短片段，固定参考音、文本、生产路径、CFG、timesteps和seed。先比较：

| 条件 | base_lm强度 | residual_lm强度 | DiT强度 | 目的 |
|---|---:|---:|---:|---|
| A：LoRA关闭 | 0 | 0 | 0 | 基模清澈度及习惯基线 |
| B：当前完整LoRA | 1 | 1 | 1 | 复现当前问题 |
| C：降低DiT | 1 | 1 | 0.3 | 检查减弱DiT能否改善质感 |
| D：关闭DiT | 1 | 1 | 0 | 定位DiT适配的影响 |

强度是相对已训练LoRA贡献的乘数，不是新的rank或学习率。`0.3`只是诊断起点，不是推荐生产预设。当前worker没有提供独立模块scale选项，需要先实现并验证实际生效，不能往options里写一个字段就宣称已经调节。

如DiT调整无法解释问题，再保持其它条件固定，单独降低或关闭residual_lm，避免一次同时改变多个模块。联合训练的模块存在协同，临时关闭一个模块可能造成失配，所以消融用于定位，不能自动作为最终配置或LM-only重训必然成功的证据。

试听分别记录：

- 清澈度、颗粒、压嗓、破音；
- 像角色程度；
- 语气、节奏、停顿和尾音习惯；
- 文本完整性和自然度。

优先短片段、少量配对，避免连续试听大量高度相似样本造成听觉适应。候选改善后用少量新文本和另一个固定seed复核，再决定后续训练方向。

### 第三阶段：根据诊断结果再规划训练

- 已确认训练样本污染或文本错配：先修数据，再比较处理前后。
- 减弱声学模块能保留习惯并改善清澈度：研究模块覆盖、分组适配强度或学习率。
- 只有某类发声或文本失败：建立该类局部案例，检查数据代表性和表达条件。
- codec/表征限制明显：记录底座边界，避免把增加步数当作通用补救。

这些均为待验证分支。本文件不宣称降低DiT必然有效，也不建议在根因未清楚时直接扩展训练步数。

## 9. 最小复现：被拒绝的削波片段仍留在输出

在主平台已安装依赖的环境中，从仓库根目录运行：

```python
import sys
sys.path.insert(0, "src")

import numpy as np
from character_tts.ingest.preprocess import cut_segments

sr = 48000
x = np.zeros(int(0.7 * sr), dtype=np.float32)
x[:int(0.2 * sr)] = 0.1
x[int(0.25 * sr):int(0.4 * sr)] = 1.0
x[int(0.45 * sr):int(0.65 * sr)] = 0.2

out, stats = cut_segments(
    x, sr,
    [[0, 200], [250, 400], [450, 650]],
)
print(stats)
print("输入削波样本：", int((np.abs(x) > 0.98).sum()))
print("输出削波样本：", int((np.abs(out) > 0.98).sum()))
```

在审查提交上的结果：报告将250–400ms列为clipped/dropped，但输入和输出均有7200个削波样本。

这是对`cut_segments`拼接逻辑的合成信号验证，未加载VAD模型，也不证明当前真实v3数据含有同样片段。实际音质归因仍需本地数据和受控试听补证。
