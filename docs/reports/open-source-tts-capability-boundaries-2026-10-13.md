# 开源 TTS 的音质、说话习惯与音色相似度：能力边界及项目优化路线

- 调研日期：2026-10-13
- 项目：`NiHaiMa123/tts`
- 仓库核对基线：`a72208137204fca99b4063686fd67c8d0c369a68`。此前代码审查基线为 `710a091fdfb9c60b2f39da09007bd9559d6cecca`，两者的项目代码相同，前者新增审查报告。
- 用户问题：LoRA 改善说话人的习惯，却影响声音质量；这是否为当前开源 TTS 的普遍能力边界？如果还有空间，如何优化？
- 前一份报告：[TTS 音质与 LoRA 效果审查](tts-quality-review-2026-10-13.md)。
- 同日补充：[Qwen3-TTS 训练破损专项核查](qwen3-tts-training-distortion-audit-2026-10-13.md)。用户已试过 Index、Vox、Fish、Qwen；Qwen 零样本清晰但音色不足，LoRA 后严重扭曲及停止失控，应优先核查其训练对齐。专项报告发现当前官方训练实现的标签、隐藏状态及文本投影问题，但尚未取得本项目实际社区补丁，不能直接判定本地根因。

## 1. 判断

**当前项目尚未证明已经达到开源 TTS 的能力上限。**

公开证据支持以下结论：

1. 音质、音色身份、说话习惯和表达控制之间确实存在跨模型的耦合与权衡。
2. LoRA 或 SFT 的音质退化不是必然结果；训练目标、数据、条件输入、checkpoint 和推理实现会影响结果。
3. 当前项目仍有官方支持但尚未充分验证的路线：双参考输入、按实际训练轮数复核早期权重、带参考音条件的微调，以及更明确的音质保持评价。
4. “干净、像角色、有她的说话习惯”是值得继续验证的目标；“面对任意新台本，完整复现原声演员的全部声学细节和表演决策”目前缺少可靠保证。

以上是研究与代码核对后的判断，不是当前权重已经获得改善的实测结论。真实训练清单、WAV 和 checkpoint 未提交 Git；本次没有运行新训练或直接试听当前本地生成物。

## 2. 三个目标必须分开评价

| 目标 | 主要关注 | 指标的边界 |
|---|---|---|
| 音质 | 清澈度、颗粒、压嗓、破音、辅音细节、异常噪声 | MOS 和质量模型可辅助，不能保证识别角色声音的所有问题 |
| 音色相似度 | 共鸣、鼻音、声线厚薄、声音身份 | 声纹 cosine 不等于原声质感或完整人耳相似度 |
| 说话习惯 | 重音、停顿、尾音、语速变化、气息及情绪表达 | 需要同文本的留出原声对照和韵律分析，不能由声纹分数替代 |

内容正确性与跨句稳定性还需要单独检查：不漏字、不重复、不异常拖长，长文中身份与表达保持一致。

CosyVoice3 论文指出，传统的发音准确率、声纹相似度和音质 MOS 不足以完整衡量情绪、节奏丰富度与声音控制能力。因此，“cosine 很高，但一听仍不对”不构成矛盾。[S1]

自然气声、喉化或角色本身的粗糙发声不应全部当作劣质。应重点判断是否出现了原声不具有的额外颗粒、压嗓或破音。对新台词，原声演员也不存在唯一可推导的表演方式，模型得到的条件信息会限制判断精度。

## 3. 跨模型证据：类似问题存在，但不能归纳为全部模型的必然结果

### 3.1 属性控制经常产生附带变化

2026年8月的《Beyond Prompt Adherence》研究评估了 CosyVoice3、VoxCPM2、Fish-Speech-S2 的5,940次生成。改变“低沉、明亮、粗糙”等属性时，输出经常还会改变其他声学或韵律特征。研究使用六个参考说话人、十段英语文本等固定条件。[S2]

**适用边界**：该研究是声音属性控制审计，不是中文角色LoRA测试；它支持“控制与保持之间存在耦合”，不能证明所有模型都会出现本项目同样的退化，也不能把其中成功率解释为普通TTS成功率。

研究同时提出少量候选的保持性筛选，说明生成分布中有可利用的候选差异。筛选能力受候选池和评价信号限制，不能保证恢复模型无法生成的声音。[S2]

### 3.2 Fish 的文档直接讨论习惯、音色及过拟合

Fish 官方微调文档说明，现有示例主要学习说话模式，音色稳定仍需要参考提示；训练更久可能进一步学习音色，也可能过拟合。文档建议尝试较早满足需求的checkpoint，并提醒对经过强化学习优化的底座继续微调可能造成分布变化和性能退化。[S3]

**版本边界**：该文档示例仍使用 `openaudio-s1-mini`，不能直接视为已验证的 S2 训练配方，也不能将其结论不加区分地套到 VoxCPM。

### 3.3 LoRA 也存在改善音质的公开结果

《Closing the Quality Gap》摘要报告，VoxCPM2 LoRA使高棉语人工MOS从3.85提高到4.23；韩语没有得到同样收益，高rank还可能退化。验证loss选择出的最佳rank与人耳MOS最佳rank不一致。[S4]

**证据边界**：本次检索取得该论文摘要信息，未成功获取完整正文；研究是约26小时数据的语言适配，不是爱弥斯声线复刻。它支持“LoRA音质下降并非必然”，但不能预测本项目的提升幅度或照搬其rank选择。

### 3.4 表面上的“模型上限”也可能是实现差异

F5-TTS 的维护者处理过训练样本很好、实际推理很差的案例：早期微调权重的EMA加载路径与训练样本生成路径不同，调整后用户反馈效果改变。[S5]

这是2025年的具体实现案例，作用是说明先排查路径的重要性；不是当前F5-TTS普遍有同样问题的证据，更不意味着VoxCPM需要同样的EMA修复。

### 3.5 VoxCPM 的相近症状仍有未定论报告

VoxCPM issue #404报告干净参考音生成后出现压缩感、爆裂或削波感，较高CFG使其更明显；检索时没有维护者最终诊断。[S6]

VoxCPM官方使用指南也提示，高CFG在困难输入上可能增加噪声和伪影。[S7]

**证据边界**：用户报告只能说明有相近症状，不能统计发生率，也不能认定根因与本项目一致。

## 4. 为什么当前项目还不能宣布达到上限

| 项目现状 | 尚未覆盖的证据 |
|---|---|
| worker构建prompt cache时使用 `reference_wav_path=None` | 双参考路径是否提高身份锚定，并改变LoRA的音质/习惯取舍 |
| v3生产使用step150，batch1、累计8 | 相同生产条件下，约2轮的step50是否有更合适的平衡 |
| 训练导出仅保留audio/text | 官方带ref_audio的条件微调是否能更好保持克隆能力 |
| 数据版本更新改变音频hash及划分 | 跨版本相同留出语音与训练组成的受控比较 |
| 已试CFG1.5、15步及种子等条件 | 新一轮应优先验证输入与适配机制，而非继续重复大范围参数搜索 |
| 既有清洗缺陷已确认，但实际污染量未知 | v3逐文件报告、入库状态和最终train.jsonl的实际审计 |

前一份报告中的数据修正仍是基础工作，但项目文档将约29秒剪切主要归于静音，不能直接推断“修清洗就会解决当前磨砂”。

## 5. 优化顺序一：双参考输入，优先用现有权重验证

### 5.1 官方支持三种参考配方

| 配方 | 信息作用 |
|---|---|
| Continuation：prompt_wav + prompt_text | 参考音作为续写上下文，提供时间及表达信息 |
| Reference：reference_wav | 独立声音身份信息 |
| Reference + Continuation | 同时提供声音身份与续写上下文 |

VoxCPM2论文比较三种配方，双路径在三个测试子集都得到最高SIM；普通中文子集SIM从续写的72.6提高到75.2。[S8]

SIM是特定声纹模型的分数，不是“人耳有75.2%像”。该结果证明配方有价值，不保证爱弥斯磨砂会改善。

项目目前在 `workers/voxcpm_worker.py` 中写死：

```python
pcache = tts_model.build_prompt_cache(
    prompt_text=prompt_text,
    prompt_wav_path=prompt_wav,
    reference_wav_path=None,
)
```

现有VoxCPM2 2.0.3 API已支持双路径，可增加实验模式将同一干净参考音传入两路：

```python
pcache = tts_model.build_prompt_cache(
    prompt_text=prompt_text,
    prompt_wav_path=prompt_wav,
    reference_wav_path=prompt_wav,
)
```

这段代码是实验接线示意，尚未改入生产。实际实现应同时记录模式、有效参考路径和hash，并让缓存key或显式失效逻辑区分参考模式，防止旧缓存复用。

### 5.2 第一轮：四条件、两段完整短句，共八条音频

| 条件 | 权重 | 输入配方 |
|---|---|---|
| A | 基模 | 当前续写 |
| B | 基模 | 双参考 |
| C | 当前v3 LoRA | 当前续写 |
| D | 当前v3 LoRA | 双参考 |

固定：

- 同一参考音和准确转写；
- 同一目标台词及文本规范化路径；
- seed123，CFG2.0，10 timesteps；
- 相同降噪与重试设置；
- 相同保存格式与试听响度处理。

选择最明显有问题的两段完整短句，避免把句子剪成不足1秒的片段。每个条件重新固定生成随机状态，记录实际重试次数、有效文本、音频hash、耗时及显存。

两项核心判断分别记录：

1. 清澈度、颗粒、压嗓、破音是否变化；
2. 角色习惯、尾音、重音和停顿的收益是否保留。

**结果解释**：

- B接近C的角色感且音质更好：当前LoRA的必要性或适配强度值得重新评估。
- D比C更稳且习惯保留：输入条件提供了新的优化空间。
- C/D都退化而A/B正常：进一步检查adapter、checkpoint和训练配方。
- 四条件都在同类发声上异常：再查参考、底座表征及推理路径。

这轮只提供定位证据，不足以证明所有新台词都能改善。候选条件随后应在少量未参与选择的台词上复核。

## 6. 优化顺序二：按实际轮数检查早期checkpoint

现有配置 `batch_size=1`、`grad_accum_steps=8`。若最终训练清单约180条，粗略换算为：

```text
数据遍历轮数 ≈ optimizer steps × 8 ÷ 180
```

| Checkpoint | 约遍历轮数 |
|---|---:|
| step50 | 2.2 |
| step100 | 4.4 |
| step150 | 6.7 |

实际轮数应以导出并被官方loader接收的样本数计算，上表不是本地训练日志的独立核验结果。

VoxCPM官方提示，单说话人适配常在1–3轮就足够，继续训练可能变差；也要求结合实际推理判断，不能只靠验证loss。[S9]

**应用方式**：

- 先用同一生产路径复核现有step50/100/150。
- 音质和说话习惯分别评价，保留取舍记录。
- 若需要新试训，在较早阶段更密集保存，避免错过平衡点。
- 不把1–3轮作为普遍硬上限；如果step150在独立文本上仍最好，继续承认这个结果。

“150步小试”不等于训练量很轻；学习率为官方模板的1e-4，也不自动证明错误或过拟合。

## 7. 优化顺序三：训练条件、数据代表性与能力保持

### 7.1 当前训练没有带参考音条件

`scripts/lora/prepare_voxcpm_lora_data.py` 接收后只写：

```python
{"audio": str(audio), "text": text}
```

没有为模型提供 `ref_audio`。这是一种可用的适配方式，但与生产时依赖参考音克隆的条件不完全相同。

VoxCPM官方微调指南建议约30%–50%样本加入同一说话人的另一段干净参考音，兼顾普通生成和参考克隆能力。[S10]

建议将此作为单独实验变量：

- 参考只从允许用于训练的同说话人素材中选取，不使用留出评测原声；
- 保持audio/text/ref_audio及验证集schema可由实际固定版本正确读取；
- 文本逐字匹配音频；
- 先统计超短样本和被处理片段，再决定清洗；
- 使用完整、干净且表达有代表性的语句，长度同时受16GB预算约束。

指南的30%–50%是起点，不是已证明适合本角色的最佳比例。

### 7.2 说话习惯需要有代表性的条件信息

游戏台词可以提供声线和局部表达，但未必充分覆盖长篇叙述的段落节奏与跨句演技。多次重复同一类材料不能自动补足缺失场景。

可建立小型参考音库：日常、轻声、开心、严肃等，每类选少量干净样本。选择参考时同时检查声音身份和场景表达，不能只取声纹cosine最高的一条。

这是基于条件机制的工程建议，需要验证；不得把情绪标签随意拼成目标台词。官方模式对控制指令的处理存在区别，尤其Hi-Fi/续写与可控克隆需要分别核对。[S7]

### 7.3 音质保持应成为选择与训练目标

Fish S2论文分别优化内容正确性、声学质量与音色相似度；CosyVoice3的能力转移微调混合目标说话人数据和原指令数据，并随机遮蔽相关条件以帮助保留能力。[S11][S1]

对本项目，先实施成本较低的多目标选择：

- 将“无明显音质退步”作为约束；
- 将音色与习惯改善作为收益；
- 对照同文本的留出原声分析重音、停顿、尾音和发声；
- 用新文本检查是否泛化，避免只选调参样本；
- 声纹、ASR、F0/HNR等均为辅助，不替代人耳。

如果这些方法仍无法平衡，再研究带条件的回放、保持性正则或偏好训练。它们属于训练目标扩展，不能直接把离散token系统的RL代码搬到VoxCPM连续扩散模型，也不能将强制模仿基模整段波形误当成单纯保持音质。

16GB下不建议将完整RL/DPO训练框架作为第一步；优先参考条件、checkpoint选择和有明确变量的短试验。

## 8. 分模块适配：保留为诊断，调整优先级

前一份报告提出的减弱或关闭DiT仍可定位声音变化，但官方微调文档明确强调DiT对声音质量的重要性。[S9]

因此执行顺序调整为：

```text
数据链路审计
→ 双参考与当前路径对照
→ 早期checkpoint复核
→ 按证据检查整体/分模块适配强度
→ 必要时改变训练配方
```

不能预设“只保留LM，就只保留说话习惯”，因为LM包含声学残差部分。联合训练的模块存在协同，临时关闭一个模块也可能引入失配。

只有在保持其它条件固定、观察到稳定改善后，才考虑将某种强度或模块覆盖作为候选方案。降低DiT不是当前已验证的生产优化结论。

## 9. 跨模型对照：少量有明确目的的候选

| 模型/路线 | 对照价值 | 当前证据的限制 |
|---|---|---|
| VoxCPM2 | 已有角色资产，优先验证较强参考配方与适配机制 | 当前LoRA配方的结果不代表其所有输入与训练方式 |
| Qwen3-TTS | 官方支持说话人SFT和参考条件 | 项目失败的是官方训练加社区LoRA patch的具体组合，不能外推全部实现 |
| Fun-CosyVoice3-0.5B | 检查另一套生成结构对中文音色和表达的平衡 | 论文部分结果属于更大模型，不可混同公开0.5B |
| Fish Audio S2 | 检查多维质量后训练底座的零样本声音与表达 | 不把旧S1微调文档作为S2配方，不立即接入新LoRA |
| IndexTTS2.5 | 已更新语速控制并保留音色/情绪分离路线 | 情绪可控不等于完整学会角色面对任意新文本的习惯 |

Qwen官方SFT文档要求ref_audio并建议同一参考用于全部样本，有助于一致性。[S12] 是否符合本地旧试验需要查实际清单和patch；本次没有取得这些文件，不能宣称已查出其具体错误。

用户补充已试过 Fish，应先核对具体版本并复用已有结果；若已试 S2，不重复将其列为新增基线。未覆盖版本是否补测取决于明确的对照目标。**当前优先级转为 Qwen 训练契约核查**，见专项报告；它不由 Vox 的双参考试验替代。Fun-CosyVoice3-0.5B 仍可作为后续候选，公开模型与路径见CosyVoice仓库。[S13] Fish S2的后训练目标及开放实现见论文。[S11]

IndexTTS2.5官方仓库记录2026-08-10发布，增加 `duration_factor` 等控制。[S14] 这是相对于用户此前IndexTTS2体验的新候选信息，不是本角色已经获得改善的证据。

模型之间的同一个seed不代表相同噪声或相同采样过程；比较应保持输入、评价目标和候选预算公平，不能仅比较各自榜单分数。

## 10. 成功标准、停止条件与能力边界判定

### 10.1 成功标准

某个候选方案需要同时满足：

- 相对基模没有明显新增磨砂、压嗓、破音或辅音损伤；
- 相对基模保留或改善角色习惯与音色；
- 内容完整，停止与时长正常；
- 改善可以在未参与调参的文本和另一个固定seed上复现；
- 长文另行检查块间衔接与身份漂移。

短片段用于定位，不能替代长文验收。评分不确定时保留不确定，不自动判候选胜出。

### 10.2 停止条件

- 某变量没有可重复收益：结束该分支，不自动扩展大规模参数扫描。
- 数据与文本问题未解决：先修数据，暂停把训练结果归因为底座能力。
- 分模块消融导致失配：保留诊断结果，不直接推广生产。
- 音质收益只来自削掉角色自然气声、喉化或表达：重新检查目标定义。
- 完成有限对照仍无法提高综合效果：记录当前最优点及限制，再决定是否投入新的数据或底座。

### 10.3 什么时候有依据认为到达边界

需要先验证数据和路径正确、较强参考配方、合理早停与适配强度，再在未参与选择的台词上确认无法兼顾目标。如果不同架构也在同类表达上失败，才更有理由怀疑数据或当前模型能力限制。

更准确的表述通常是：

> 这个底座、这批角色数据和当前训练预算下的实用上限。

它不等于整个开源TTS行业的上限。编码和生成表示通常有损，“高质量48kHz输出”也不等于逐细节恢复原始配音；codec roundtrip与自由生成输入分布不同，不能用其中一条结果直接宣布另一条路径的音质天花板。

**下一项验证应按故障选择：Qwen 的严重破损及停止失控，先按专项报告核对训练对齐与加载；Vox 的质感与习惯取舍，再完成第5节八条双参考对照及第6节早期checkpoint复核。**
